# Contributing to palm-analytics-dbt

Thanks for looking at this project. It is a public analytics-engineering
showcase; small, focused contributions are welcome.

## Ground rules

- **Do not commit data artifacts:** `palm.duckdb`, `palm_lake/`, `target/`,
  `logs/`, `dbt_packages/`, `.venv/`, `ingestion_manifest.json`,
  `dashboard/sources/palm/palm.duckdb` are all git-ignored and rebuilt by the
  pipeline. Never force-add them.
- **Pinned toolchain:** `dbt-core==1.12.3` is pinned in `requirements.txt`.
  Do not unpin or bump without verifying CI (`dbt.yml`) stays green.
  `duckdb>=1.4.4` is the floor (DuckLake support).
- **Generated file — do not hand-edit:**
  `models/semantic_layer/sl_metrics_daily.sql` is generated by
  `semantic/compile_metrics.py` from `models/marts/_marts__semantic.yml`.
  Change the YAML, then regenerate:
  `dbt parse --profiles-dir . && python semantic/compile_metrics.py`.
- **Shared macro:** `macros/agronomy_rules.sql` must stay in sync between the
  historical and forecast paths — change it in one place and check both.

## Local setup (Windows)

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
python ingestion/load_raw.py
dbt deps && dbt parse --profiles-dir .
python semantic/compile_metrics.py
dbt build --profiles-dir .
```

Dashboard: `cp palm.duckdb dashboard/sources/palm/palm.duckdb && cd dashboard && npm install && npm run dev`.

On Linux/macOS CI the equivalents are `python` / `dbt` directly
(no `.venv/Scripts/` prefix, no `--profiles-dir .` needed if configured).

## Workflow

1. Open or pick an issue; small PRs, one concern each.
2. Run `dbt build --profiles-dir .` locally — expect **PASS=92, WARN=0, ERROR=0**
   (see `PROJECT_STATUS.md` §7 for the current anchor).
3. If you touched the semantic registry, regenerate (above) and confirm the
   committed SQL is byte-identical to the generator output.
4. `dbt docs generate` should succeed; Evidence pages you touched should build
   (`npm --prefix dashboard run build`).
5. PRs run `dbt build` + Pages deploy in CI. Do not merge on red.

## Gotchas

- **DuckLake is single-writer**: never run two ingests in parallel locally.
- Forecast window is always **today+1…+7**; history pins to `2026-06-30`
  unless `PALM_USE_LIVE_DATE=1`. Don't "fix" one side without the other.
- Synthetic fallback is **loud by design** (manifest + CI warnings); commodity
  is always synthetic — see `PROJECT_STATUS.md` §3 before "fixing" it.
- Unit tests are **mutation-verified**: flipping an agronomy `<` boundary must
  fail them. Don't weaken fixtures to make red green.
